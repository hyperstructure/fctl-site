Features/Sessions

Agents at work, in plain sight.

A session is one agent on one task: a sandbox of its own, a branch of its own, and a transcript that streams as it thinks, runs commands and edits files. Follow it from your desk or your phone, steer it with a message, and let fctl call it back when its pull request needs it.

Open the app Start your first session →

Live To the token

Transcripts stream as Claude writes them: its thinking, the commands it runs, the files it edits and the diffs they leave.

Steer Any time, from anywhere

Your message reaches the agent at its next step. Interrupt it mid-command, or stop it, from the app, the terminal or your phone.

Ship Pull requests, tracked

Each session's pull request shows where you look, with its checks as GitHub runs them and the moment it merges.

Return Called back when needed

A failed check, a comment, a conflict with main: fctl brings the agent that opened the pull request back to deal with it.

One page holds the whole story.

Every session has a page: what was asked, everything the agent did since, and what it changed. Runs of commands fold into a line that opens when you want the detail, so a two-hour session still reads in a minute. Memory notes, screenshots and retrospectives show where they happened.

The new session view, a click away in any session's menu, reads it in turns: each message opens a card, what the agent did about it hangs from the card on a thread, and each turn ends with how long it took and the files it edited. The agent's plan stays beside it, checked off as it goes, and a line above the message box says what it is doing now.

  • See who else is watching. Avatars in the header show everyone with the page open.
  • Steer it like a colleague. A message waits for the agent's next step, so nothing it is in the middle of breaks.
  • Keep score on the side. Files changed, commits pushed, the pull request and its checks, and the tokens it used.

Every change, line by line.

Click a file under Changes and its diff opens over the page: highlighted as its language is, numbered as the file is, with the words that changed marked. j and k step through the session's other files, and s lays them side by side. The agent sends its diffs as it works, and they change as you read: the lines it writes come in where you look, while the ones you're reading stay where they are. They're still there after the session has stopped.

  • Any language. Rust, TypeScript, Python, Terraform, Dockerfiles, lockfiles, .env files and many more.
  • Before it's pushed. Uncommitted work counts: whatever the branch changed since it left its base.
  • In your terminal, too. fctl diff platform#437 prints them as git does, ready for git apply.

When the pull request needs it, the agent comes back.

Pushing isn't the end of the job. When a check fails, a reviewer writes to @fctl, the branch falls into conflict with main or the pull request merges, fctl tells the session that opened it what happened. The agent picks the work back up on the same branch, with everything it knew.

Each project chooses which of these come back, and what stays a notice on the page.

How follow-ups work →

When it needs you, it asks.

Some calls are yours to make. An agent that needs one asks with fctl ask, offers the answers it sees, and ends its turn. The question waits above the message box, and at the top of Needs you for everyone who follows the session. A click sends that answer as your reply, or write your own: the agent goes on from there.

  • Where you'll see it. On the session's row on the Agent Floor, on the pull requests page, and in a notification as its turn ends.
  • Only what it can't find out. fctl tells agents to ask for a decision only a person can make, access or an answer, one question at a time.
How questions work →

Your factory, at a glance.

Home is the Agent Floor: everything at work across your workspaces, what waits for you, and what finished while you slept. Start the next task from the box at the top. It goes to the project, model and effort you pick, and joins the floor a moment later.

  • Working, waiting, paused. Each row says which, with its ticket, branch and pull request.
  • What needs you, on top. The sidebar lists what waits for you: an agent's question, a failed check, a pull request ready for your review.
  • Your plan's limits in view. How much of the five hours and the week your Claude plan has left.
  • On your phone, too. The app installs to your home screen, notifies you when a session waits for you, and shows what it changed, long lines wrapped.

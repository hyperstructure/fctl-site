Features/Access tokens

Let other tools start agents.

A chat bot, a CI job, an issue tracker's automation, another agent: anything that can make a web request can start a session as you. Give it a token that does just that, in the projects you choose, for as long as you say. It never reaches your account, your team's settings or your other tokens.

Make a token Start agents from other tools →

What Run, read or all

Bots and CI run sessions; dashboards read them. Everything you can do is for your own scripts.

Where Some projects

All of yours, a few, or every project of a workspace, those made later included.

GitHub Comment, not push

Hold a token's agents to commenting or reading, even in projects where agents may push.

When Then it stops

A week, a quarter, a year, or until you revoke it. The audit log says which token started what.

Three questions, one sentence.

What may it do, where, and for how long. As you answer, the form says in plain words what the token will be able to do, and what it never will. It's shown once, ready to paste as FCTL_TOKEN or an Authorization header.

Making one is also one of the things fctl can ask you to confirm with your passkey or a code first, so a stolen browser session can't mint itself a key.

Confirming it's you →

One request from anywhere.

Point a tool at a schedule that runs when asked, and send what it knows along: an issue that was just filed, a deploy that went out, a customer's report. Each request starts a session with the schedule's task and that context.

  • Or the whole CLI. With FCTL_TOKEN set, every fctl command works within the token's limits.
  • Reviews from your own CI. A token for GitHub Actions can start review agents that comment and never push.
noor@Noors-MacBook-Pro ~

fctl token "Issue triage" --access run -p shop --github comment --days 90
